# Как собрать пакет для миграции (для новичка)

> **Это учебная (смоук) сборка** — собрать пакет, увидеть, что цепочка работает,
> понять из чего она. Профиль `astra-gcc` (системный gcc).
>
> **Поставляемые пакеты** собираются профилем `lin-gcc84-x86_64` **внутри Docker**
> `grpc-tc-mirror` (gcc 8.4) — это **отдельный шаг мейнтейнера**, в одиночку не делай:
> см. `README.md` и `HELP.txt` блок `[4]`. **Смоук-пакеты на ProGet не публикуй** —
> они собраны не тем компилятором и для поставки не годятся.

## Что мы делаем (простыми словами)

Берём чужую C++-библиотеку (gtest, zlib, grpc…), собираем её инструментом **Conan**
и упаковываем в **`.nupkg`** — файл в старом формате, который понимают наши продукты
(`grpc_sdk`, `el_conf`). `.nupkg` — это просто **zip**: заголовки (`.h`) +
скомпилированные `.a`.

## Что нужно

- Машина **Astra** (Linux), всё **offline** (интернет не нужен и недоступен).
- Репозиторий уже склонён. Где именно — посмотри `ls ~` (может быть `~/conan-master`
  или `~/conan-recipes`). Все команды ниже запускай **из корня репозитория**.

## Шаг 0 — настроить один раз

```bash
sudo ./test-astra/install_deps.sh    # системные пакеты (gcc, cmake, python)
./test-astra/setup.sh                # установить Conan из локальных файлов
source venv/bin/activate             # включить окружение
```

**Ожидаемо:** `conan --version` печатает `2.29.0`.
**Если `conan: command not found`** → ты не выполнил `source venv/bin/activate`
(его нужно повторять в **каждом новом** терминале).

## Шаг 1 — собрать пакет

```bash
./test-astra/run_test_zlib.sh    # zlib  → output/zlib.*.nupkg
./test-astra/run_test.sh         # gtest → output/googletest.*.nupkg
```

**Ожидаемо:** в конце `[OK]`, и в каталоге `output/` появился `.nupkg`. Идёт пару минут.
**Если падает на `tool_requires`/cmake** → потерян флаг `-pr:b` (в скриптах он есть;
всплывает при ручном запуске).
**Если `Permission denied`** → запусти через `bash ./test-astra/run_test_zlib.sh`.

> Имя пакета в файле часто **отличается** от Conan-имени — так требует legacy-схема:
> `gtest → googletest`, `abseil → absl`, `c-ares → cares`. Поэтому ищи `googletest.*`,
> а не `gtest.*`.

## Шаг 2 — проверить, что получилось

```bash
ls -lh output/
unzip -l output/zlib.*.nupkg | head     # .nupkg это zip — смотрим внутрь
```

**Хорошо, если** внутри есть `lib/native/.../*.a` и папка `include/` — значит цепочка
сборки отработала. Это и есть цель учебной сборки.

> В имени файла зашит компилятор. У учебной сборки это `gcc8` (смоук). У поставляемых
> пакетов — `gcc84` (из Docker, см. забор в начале). Не путай и смоук на ProGet не лей.

## Дальше — по мере роста

- **Собрать grpc целиком (учебно):** `./test-astra/run_test_grpc.sh`
  (grpc 1.78.1 + 6 зависимостей → 7 файлов в `output/`). Идёт **~15–25 мин — не прерывай**.
- **Собрать пакет вручную** (если готового скрипта нет): `README.md`, раздел
  «Добавление нового пакета» (там точные команды `conan create` + `conan install --deployer`).
- **Добавить новую библиотеку в миграцию:** там же в `README.md`. Первый раз — вместе
  с тем, кто в проекте.
- **Поставляемый `gcc84`-пакет и публикация на ProGet:** отдельный шаг мейнтейнера —
  `HELP.txt` блок `[4]`. **В одиночку не делай** (легко отгрузить пакет не тем
  компилятором и тихо сломать сборку продуктов).

## Если застрял

- Частые ошибки новичка: забыл `source venv/bin/activate`; запустил без `-pr:b`;
  перепутал каталог результата (`output/` против `output-grpc-1601-upstream/`).
- Глубже — `HELP.txt` (но там в основном экспертная диагностика Docker/ARM, не для новичка).
- Не уверен про структуру `.nupkg` или публикацию — **спроси, не угадывай**.
